
- **The Toolbelt's unit cannot reach the internet, so anything it needs from outside goes through a loopback proxy in its own unit (found 2026-10-04, the PR canary-test check read `HTTP 0` from GitHub).** `IPAddressDeny=any` is deliberate (the Toolbelt holds read tokens for most of the homelab). Rule: never widen that unit's egress; add a narrow proxy unit instead (`aiops-toolbelt-ghread`: 127.0.0.1:8092, two GET paths for one repository, no credential, internet yes and private ranges no, resolvers allowed back in because `IPAddressAllow` beats `IPAddressDeny`) and point the Toolbelt at it (`--github-read-url`). Symptom: a Toolbelt feature that calls out answers HTTP 0 / `URLError` while `curl` from the same host works; `systemctl show aiops-toolbelt -p IPAddressDeny` says `any`. The same split already exists for NetBox (`placement_sync.py`) and Vault (`aiops-toolbelt-token`).
