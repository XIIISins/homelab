# Known gotchas — CI / GitHub Actions / branch rulesets

*Procedure: [`../procedures/ci.md`](../procedures/ci.md). Decision: [`decisions.md`](../operations/decisions.md) "CI gate + branch ruleset".*

- **gitleaks must be ≥ 8.29.1 or the repo's allowlists silently don't apply.** `.gitleaks.toml` uses `[[allowlists]]` with `regexTarget = "line"` + `condition = "AND"`. On 8.24–8.28 the file parses but the allowlists are ignored: the scan reports 6–9 "leaks" that are SealedSecret ciphertext, ExternalSecret Vault *paths* and a 1Password item ID. 8.18 additionally has no `git` subcommand. CI pins **8.30.0** (sha in `ci.yml`); full history is clean on it. Symptom of a too-old local binary: false positives only in `k8s/**/*secret*.yaml` + `.config/scripts/homelab.sh`.
- **gitleaks on a shallow clone** treats the grafted boundary commit as "adds every file" and re-reports the whole tree. CI checks out with `fetch-depth: 0`; locally `git fetch --unshallow` before judging a scan.
- **kubeconform silently skips files without a `.yaml`/`.yml`/`.json` extension** — a validator fed `mktemp` output validates nothing and exits 0. `ci-k8s.sh` uses `mktemp --suffix=.yaml` and fails if it schema-checked 0 resources. When adding validators to CI: **always negative-test** (inject a known-bad field, confirm exit ≠ 0).
- **`workflow_dispatch` returns 404 until the workflow file exists on the default branch.** To test a new workflow before merging, open a (draft) PR — `pull_request` runs use the PR branch's copy.
- **A required check that is skipped by a workflow-level `paths:` filter never reports → the PR is blocked forever.** `ci.yml` always runs; per-job `if:` skips; `CI gate` (`if: always()`) folds `skipped` into pass. Don't "optimise" this away.
- **`terraform validate` still needs required provider arguments** (hashicorp/vault wants `address` even though validate never connects). `ci-terraform.sh` exports placeholder `VAULT_ADDR`/`VAULT_TOKEN`; if another provider fails validate with "Missing required argument", add a placeholder env there, not a real credential.
- **`terraform fmt -check` fails on hand-aligned HCL** (tables aligned with extra spaces, `# comment` columns). Run `terraform fmt -recursive terraform` before pushing; don't hand-align.
- **ruleset `required_check.integration_id = 15368` is the GitHub Actions app.** Omitting it lets *any* app satisfy the check name; a wrong id makes the check unsatisfiable. Check name = the job's `name:` (`CI gate`), not its key.
- **Imported `github_repository`:** the first plan can show unrelated attribute diffs (provider defaults vs real settings). Read it before applying; never apply a plan that flips `has_*`, visibility or topics.
- **Sandboxed sessions can't run everything locally:** Galaxy and the Terraform registry are egress-blocked in Claude Code remote sessions, so `ansible-lint` and `terraform validate` first run for real in Actions. Use a draft PR to iterate.
- **ansible-lint 24.12 has no `--format github`** (choices: brief/full/md/json/codeclimate/quiet/pep8/sarif). It detects GitHub Actions itself and emits annotations — run it bare. First CI run failed on this flag.
- **ansible-lint crashes (IndexError in `ansiblelint/utils.py`) on a Jinja syntax error in any templated string** — here Zabbix LLD macros like `{#RESOURCE.TYPE}` (Jinja reads `{#` as a comment start). Mark such literals `!unsafe "{#...}"` (runtime result is identical). Any new Zabbix LLD macro in a playbook needs the same.
- **ansible-lint baseline = `ansible/.ansible-lint-ignore`** (125 pre-existing findings muted per file+rule on 2026-10-01: name casing, partial-become, role names with hyphens, var-naming, …). Regenerate-and-diff with `ansible-lint --generate-ignore` only to *remove* entries; locally it also emits `syntax-check[unknown-module]` for collections you haven't installed — delete those lines, CI installs the collections.
- **`ansible-galaxy collection install -r requirements.yml` takes ~6 min on a cold runner** (Galaxy is slow); the job has a 20-min timeout and 3 retries. Every job carries `timeout-minutes` — the default is 360 min, which would hold the required check hostage if a step hangs. Now cached (actions/cache keyed on `requirements.yml` + `ci-requirements.txt`, saved right after a successful install) — a cold run only happens after a pin bump or a 7-day eviction; see [`procedures/ci.md`](../procedures/ci.md#cache-keys--bump-checklist). Gotcha: plain `actions/cache` saves only if the *whole job* passes, so the galaxy cache uses split `restore`/`save` steps — otherwise a lint finding discards the download every time.
- **Terraform lock files (`.terraform.lock.hcl`) are gitignored**, so the provider cache can't key on them; it keys on the module's `*.tf` with a `restore-keys` fallback (an edit reuses the previous provider set, `init` fetches only what's missing).
- **The kubeconform CRD schema cache freezes a float** (datreeio catalog `main`). Bump `KUBECONFORM_SCHEMA_EPOCH` in `ci.yml` when a chart/operator bump needs a refreshed schema, or a stale schema can mask (or invent) a validation result.
- **A Galaxy 502 mid-install poisons the retry:** the partial `collections/` makes attempt 2 print "Nothing to do. All requested collections are already installed" and exit 0, leaving dependencies (e.g. `community.general`) missing → ansible-lint `syntax-check[unknown-module]` on every playbook (main run 36862586742, 2026-10-01). The loop now `rm -rf collections` before each attempt.
- **Importing `github_repository` nulls every unset argument:** the plan showed `description`, `has_issues`, `has_projects` going to null. Pin every setting you want kept (done in `terraform/github/main.tf`) and read the first plan line by line.

- **The `main` ruleset's bypass actor is the repository Admin role, so a PAT on an admin account can push to `main` (found 2026-10-04).** `rulesets/24308920` has `bypass_actors: [{actor_type: RepositoryRole, actor_id: 5, bypass_mode: always}]`. A fine-grained PAT with Contents write inherits its owner's role, so a token minted on the owner's own account bypasses the required `CI gate` and direct-push rejection. Why it matters: `main` is the K8s deploy (Flux). Symptom: none until it is used; check with `GET /repos/<repo>` (`permissions.admin`) using that token. Rule: any token handed to automation (the 10h2 dispatcher) must belong to a write-only machine user; the dispatcher refuses an admin/maintain token. See [`procedures/aiops-author.md`](../procedures/aiops-author.md) and decisions "The dispatcher refuses a GitHub token...".
- **GitHub cannot mint PATs through `gh` or the API; and `X-Accepted-GitHub-Permissions` is only sent to fine-grained/app tokens (found 2026-10-04).** An OAuth login (`gho_...`, what `gh auth login` stores) gets only the old `X-Accepted-OAuth-Scopes`. To learn the exact permissions an endpoint needs, call it with the fine-grained token and an invalid body (a 422 still carries the header) and never with a body that could succeed: a probe at `PUT /pulls/<n>/merge` or `PATCH /pulls/<n>` is a real write.
- **A diff line that starts `+++` inside a hunk is added content, not a header (found building the 10h2 secret scan).** A scanner that skips `+++` lines lets `++password=...` through. `aiops/author/dispatcher.py` tracks hunk state (`added_lines`); keep that when touching it.
