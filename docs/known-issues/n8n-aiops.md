# Known gotchas — n8n AIOps agent (Gná)

*Phase 10d1 (2026-10-02). Covers the dedicated agent instance on LXC 1121, not the asgard-K3s n8n (see [`../services/n8n.md`](../services/n8n.md)). Procedure: [`../procedures/aiops-diagnosis.md`](../procedures/aiops-diagnosis.md). Decisions: [`../operations/decisions.md`](../operations/decisions.md) ("AIOps agent: dedicated n8n on Gná").*

All of these were found by running the real thing locally (pinned n8n 2.23.1 + a real Caddy 2.11.4 + a mock Discord) before the first deploy, not by reading docs.

- **`/healthz` answers before active workflows register — a readiness probe on it races the webhook.** After a restart n8n serves `/healthz` while it is still on "Start Active Workflows"; a POST in that window gets `404 The requested webhook "POST aiops/zabbix" is not registered`. Probe the *route* instead (an unauthenticated POST must return **403**, which proves registration and auth and posts nothing): that is what the role's smoke test does, with retries. Also why the plumbing test is not "start, then immediately curl".
- **CLI import needs an owner, and n8n only creates one in the UI — unless it is env-managed.** `n8n import:workflow` assigns to the owner; a fresh instance has none, which would force a manual first-run step. Set `N8N_INSTANCE_OWNER_MANAGED_BY_ENV=true` + `_EMAIL` + `_PASSWORD_HASH` (bcrypt) and the owner is created on first start ("Owner was set up successfully"). The role derives the hash with the `bcryptjs` that ships inside n8n and a salt derived from the password, so the env file (and therefore the service) is byte-stable across runs; a random salt would restart n8n on every converge.
- **`publish:workflow` only takes effect after a restart** ("Changes will not take effect if n8n is running"). Import -> publish -> restart is the sequence; the role gates it on a checksum so n8n is restarted only when a workflow, token or the n8n version changed. A restart interrupts any in-flight agent run, so do not "touch" the import.
- **n8n 2.23.1 needs Node ≥ 22.22; Debian 13's packaged Node is older.** The role installs the official tarball by version + sha256 (same idea as the pinned Gatus binary). When bumping n8n, read its `engines.node` first; when bumping Node, take the sha256 from `https://nodejs.org/dist/<ver>/SHASUMS256.txt`.
- **`MemoryDenyWriteExecute=yes` (used for Gatus) breaks Node.** V8's JIT needs writable+executable pages; the n8n unit omits it. The rest of the Gatus sandbox applies. `SystemCallFilter=@system-service` is in place but was not exercised on Debian 13 before the first deploy: if n8n dies with `SIGSYS`, `journalctl -u n8n` + `systemd-analyze syscall-filter` and relax narrowly rather than dropping the filter.
- **The Discord node cannot create forum threads.** Its webhook mode has no `thread_name` / `thread_id`; use an HTTP Request node (`POST <webhook>?wait=true` with `{"thread_name":…}` creates the thread, follow-ups use `?thread_id=<channel_id>`). The URL therefore comes from an expression, `{{ $env.AIOPS_DISCORD_URL }}`, which needs `N8N_BLOCK_ENV_ACCESS_IN_NODE=false`. That also exposes the other variables in the env file to workflow expressions, which is why the encryption key is a **file** (`N8N_ENCRYPTION_KEY_FILE`, 0400) and the only secret left in the environment is a post-only webhook. Always send `"allowed_mentions":{"parse":[]}` so alert text (which is attacker-influenceable) can never ping `@everyone`.
- **Webhook auth is a credential, not a path secret.** The workflow JSON is committed to a public repo, so the ingest token cannot sit in the webhook path. A `headerAuth` credential (`aiops-ingest-<source>`) is imported from Vault by the role; the workflow references it by id+name only. The CI lint rejects a workflow with an inline secret, an unauthenticated `aiops/*` webhook, or a credential carrying data.
- **A webhook that waits for the workflow turns a slow agent into a failed alert send.** `responseMode: onReceived` answers 200 immediately. The lint requires it for every `aiops/*` webhook; the independence test (stop n8n, alert still reaches Discord) is the other half.
- **Caddy: a host-qualified listen address (`127.0.0.1:18081`) turns on auto-HTTPS; use the bare `:8081` form the role uses.** Symptom: `Client sent an HTTP request to an HTTPS server`. Restricting a site to `/webhook/*` works with `extra_directives` (`@notwebhook not path /webhook/*` + `respond @notwebhook 404`): Caddy orders `respond` before `reverse_proxy` inside the allowed handle. Verified with `caddy validate` and a request matrix (allowed source: `/webhook/*` proxied, `/`, `/rest/login`, `/healthz`, `/webhook-test/*` 404; other source: 403 everywhere).
- **npm resolves n8n's transitive dependencies at install time** (~2150 packages); only `n8n@2.23.1` is pinned, there is no lockfile. Two installs a month apart can differ below the top level. Accepted for 10d1 (the version is pinned and the host is rebuildable); shipping an `npm-shrinkwrap.json` is an open item.
- **Pre-flight `lookup(...)` with `errors='ignore'` turns an absent secret into an empty string** — by design, so the assert can name the missing Vault path and the fix. If the play fails at "Assert the secrets are present", read the message; it lists which secret is Terraform-minted (apply `terraform/vault` from the main checkout) and which is operator-seeded.
