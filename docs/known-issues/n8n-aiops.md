

- **`IPAddressDeny=` on a unit applies to its WHOLE cgroup, `ExecStartPre=+` helpers included (2026-10-02, Toolbelt API).** The first version ran the Vault token loader as `ExecStartPre=+` inside the API unit that has `IPAddressDeny=any`; the loader timed out reaching Vault (`URLError: timed out`, unit `Failed to start`). `+` lifts the sandbox directives (`ProtectSystem=` etc.) but not the cgroup BPF filter. Fix: the loader is its own oneshot unit (`aiops-toolbelt-token.service`, no IP filter, `RuntimeDirectoryPreserve=yes`) and the API unit runs `ExecStartPre=+systemctl restart aiops-toolbelt-token.service`, which also refreshes the token on every start. A timeout (not `connection refused`) from a helper inside an `IPAddressDeny=` unit means this. The local loader test cannot show it; only the unit on the host does.
- **Toolbelt API reachability check:** from Gná an anonymous `/stats` returns 403 and `/healthz` 200; from any other host (Hugin tested) the connection times out, because the unit's `IPAddressAllow=` drops it before the app's own allow-list sees it.
- **The Toolbelt unit's `IPAddressAllow=` now includes the homelab egress range (10.0.0.0/8) for the `reach.tcp` probe, so the cgroup filter no longer drops other LAN hosts' inbound packets (2026-10-02).** The app-level allow-list (`--allow`, Gna only) still refuses them with 403, and that is tested, but a Hugin probe now gets 403 instead of a timeout. If the cgroup layer must be strict again, move `reach.tcp` to a separate helper unit and shrink `aiops_toolbelt_egress_allow` to the specific read-only backends.
- **Read-only backend credentials reach the Toolbelt only through the root loader, and they are optional at start (2026-10-02).** `aiops_toolbelt_credentials` maps a name to a KV path; the loader writes `/run/aiops-toolbelt/creds/<name>.json` (0400, service user). A credential that is not minted yet logs `WARNING: credential '<name>' not loaded` in `journalctl -u aiops-toolbelt-token` and its tool answers 501 `credential ... is not available`; it does NOT stop the API. After minting one, `systemctl restart aiops-toolbelt-token` (or restart the API, which restarts it). A credential that vanishes from Vault also removes its stale file on the next run.
- **`pve.*` tries every cluster node in turn.** Any member answers for the whole cluster, so a dead node (the Skuld freeze) does not blind the tool; `pve.node_status` for a dead node reports the cluster's own view (`offline`) and makes no call to the node itself. The TLS certificate is not verified (self-signed, management VLAN, PVEAuditor-only token).
- **Prove a PVE token is read-only against a NON-EXISTENT vmid, never a real guest or `/nodes/<n>/status`.** PVE checks permission before existence, so a stop/start/delete/snapshot/config call on vmid 999999 answers `403 Permission check failed (/vms/999999, VM.PowerMgmt)` for a PVEAuditor token, and would answer a harmless `does not exist` if the token ever gained write rights: either way nothing real is touched. A node-level call such as `POST /nodes/<n>/status` (shutdown) must never be used as a probe.
- **n8n Agent 3.x cannot use the HTTP Request Tool; stay on Agent 2.x (2026-10-02, 10d3).** Symptom: the execution errors with `The node "@n8n/n8n-nodes-langchain.toolHttpRequest" has a "supplyData" method but no "execute" method`, after the correlation wait and before any tool call. Agent 3.x routes tools through an engine path that needs `execute`. `aiops/n8n/build_ingest.py` pins `AGENT_VERSION = 2.3`; re-test before bumping.
- **The Anthropic chat node's default `thinking: disabled` is rejected by current models (HTTP 400).** The message says to send `between_tools` instead, which the node does not offer. The model node uses `thinkingMode: adaptive` with `effort: low` (and no `temperature`).
- **HTTP Request v4 takes headers as `headerParameters.parameters`; the HTTP Request TOOL takes `parametersHeaders.values`.** Using the tool's shape on the normal node sends no header and no error; the replay header silently never arrived and the run looked like an ordinary alert.
- **Read the real error of a failed execution from the database, not the log.** n8n logs only `Workflow execution finished with error`. The error objects are in `execution_data.data` (a flatted JSON array) of `/var/lib/n8n/.n8n/database.sqlite`: load the array, find dicts with `message` + `name` and resolve the index references. That is how the Agent-3.x and `thinking` errors above were found.
- **A failure INSIDE the agent's sub-nodes ends the whole execution; `onError: continueErrorOutput` on the agent does not catch it.** The incident is then left in `running` with nothing posted. The Toolbelt therefore stops counting a `running` incident against the queue once it outlives `run_wall_clock_seconds` (it is reported `timed_out` in `/group/<id>`), so stuck runs cannot fill the queue and stop all new analysis. An n8n error workflow that posts a fallback thread is the remaining gap.
- **Replay runs are isolated from real alerts on purpose.** An ingest with `X-AIOPS-Replay` gets a per-run fingerprint and its own correlation group (`replay:<scenario>`), so a test can never be deduped away by, nor suppress or join, a genuine alert. Two replay events inside one 90 s window are one incident (a burst); the harness waits out the window between runs. The first attempt at the acceptance scenario was silently swallowed as a `duplicate` of an earlier run before this isolation existed.
- **Model ids are workflow settings, not secrets:** `claude-sonnet-5-5` by default, `claude-opus-5-5` when the Toolbelt's `model_hint` says opus (3+ alerts, or a multi-alert critical group with no known hypervisor). Change them in `aiops/n8n/build_ingest.py` (`SONNET`, `OPUS`) and regenerate.
- **NetBox: ANY `brief` query parameter means brief mode, even `brief=0` (2026-10-03).** The placement sync sent `?brief=0` and got objects without the `device` field, so it saw zero placed guests (the job's own sanity check, `--min-guests`, caught it and kept the previous map). Never send `brief` at all; the test's fake NetBox now mimics this.
- **NetBox lets every user list their OWN tokens; that is not a permission you can remove.** The read-only proof therefore asserts the view-only token sees exactly one token, its own (`count == 1`, owner `aiops-ro`), instead of a 403. It cannot read other users, create anything, or see any other token.
- **The placement sync keeps the previous map whenever NetBox is down, refuses the token, or answers with fewer than `aiops_toolbelt_placement_min_guests` placed guests.** Grouping then degrades to the last known map, never to "unplaced". The API hot-reloads the file on mtime change (`placement_loaded` in the audit log).
- **`systemd: state=started` on a oneshot reports `changed` on every run.** A "run it once now" convenience step must be guarded by `stat` of its output (the placement map), or the role never converges to `changed=0`.
- **Frigg reboot test, 2026-10-03:** after `ansible.builtin.reboot` (about 30 s), `aiops-toolbelt`, the repo and placement timers, `frigg-ssh-agent` (fleet key reloaded from Vault), `tailscaled`, `zabbix-agent2`, `vlagent`, `claude-remote-control` and `frigg-reauth-listener` were all active; `/run/aiops-toolbelt/{token,creds/*}` had been re-created by the root loader with no manual step; an acceptance run through the rebooted Toolbelt passed.
- **UCG zone policies: order is per zone pair, and EDITING a policy moves it to the bottom of the custom list (2026-10-03, Gná egress).** The Gná allow rules did nothing until `Allow OS Updates` was dragged back ABOVE `Egress Default Deny`: after the source field was edited it had been re-appended below the deny, so the deny matched first. After every edit, open the zone-pair view (click the Internal → External cell of the zone matrix, not the unfiltered list, where unrelated pairs interleave and the order looks arbitrary) and check the allows are above the deny. A first suspicion that the gateway resolves CDN hosts differently from AdGuard was wrong: the gateway and AdGuard return identical answers for all six hosts, and domain-destination rules matched once the order was right.
- **A UCG policy change takes about a minute to apply.** A probe run seconds after pausing the Deploy Window still saw it open; a re-run a minute later showed it blocked. Wait ~1 minute before judging a rule change.
- **UCG policy destination is ONE type: Any, App, IP, Domain or Region.** You cannot mix domains and IPs in one policy; a mixed need is two policies, and each must then be placed above the deny.
- **The UCG list shows an allow's hits only if it matched; to see WHY something is blocked, enable `Syslog Logging` on the deny.** The CEF log line names the blocking policy, the destination IP and the source client (`UNIFIfirewallPolicy=`, `dst=`, `UNIFIsrcClientIp=`): that one line identified the cause (a Debian Fastly address hitting the deny).
- **Re-test the egress rules with `curl -m 8` from Gná against a should-work list and a should-be-blocked list (Discord, Anthropic, Debian, Zabbix vs example.com, Google, npm, GitHub), and again ~15 minutes later.** Internal destinations (Toolbelt on Frigg, Hugin, AdGuard, VictoriaLogs) are intra-zone and never cross these rules.
- **`kubectl auth can-i get nodes/proxy` tests the node NAMED "proxy", not the proxy subresource (2026-10-03).** `resource/name` is kubectl's name syntax, so the check returned `yes` (a `get` on nodes is allowed) and also made `pods/log` look right for the wrong reason. Use `--subresource=proxy|exec|attach|portforward|log|token`. `aiops/tools/mint_kube_ro.py` does, and its matrix covers every wall of the read-only ClusterRole.
- **The Toolbelt's Kubernetes credential is a static ServiceAccount token Secret, not a 1-hour minted token.** The plan assumed the Frigg loader would mint short-lived tokens, but TokenRequest needs a credential allowed to create tokens, i.e. cluster-admin in a boot-time root process. A static read-only token is the same trust class as the Zabbix, NetBox, Proxmox and Semaphore ones: Vault-held, revocable (delete the Secret `aiops/aiops-readonly-token`), unable to read secrets or act.
- **Semaphore: the `guest` project role is read-only, but any authenticated user can list users (id, name, username only) and a user-create attempt answers 401, not 403.** `aiops/tools/mint_semaphore_ro.py` expects exactly that. Task history and a redacted tail of failed-run output are what the `semaphore.tasks` tool returns.
- **Flux picks up a merge within its interval; `flux reconcile source git flux-system` then `flux reconcile kustomization infrastructure --with-source` makes it immediate** (allowed by the repo's deploy rules: the merge IS the deploy, the reconcile is only a nudge).
- **The watchdog is the recovery path for a diagnosis run that dies mid-way.** `aiops/n8n/workflows/watchdog.json` (generated with the ingest workflow) polls the Toolbelt's `GET /watchdog` every 5 minutes. It returns incidents that have been `running` longer than `run_wall_clock_seconds` (default 600 s) with no thread, each with a ready-made fallback post. The workflow posts it and moves the incident to `posted`. Because the cap is far above a normal run (tens of seconds), a slow-but-alive run is not mistaken for a dead one; a dead one therefore gets its fallback thread within ~15 minutes. If the Discord post fails the incident stays `running` and is offered again on the next tick.
- **Decision threshold for adding a tool to the agent prompt:** the prompt carries a question -> tool table; every tool named in it must exist in the Toolbelt allow-list (a test enforces it), and the tool description the model sees is generated from the allow-list, so adding a tool is: handler + `SPEC` entry + a prompt row + regenerate (`python3 aiops/n8n/build_ingest.py`) + re-run the scenarios.
- **The Toolbelt reaches VictoriaLogs/VictoriaMetrics through DEDICATED hostnames (`logs-read.`, `metrics-read.niflheim.xiiisins.com`), not the UI hosts.** The UIs (`logs.`, `metric.`) sit behind Authentik forward-auth and call the same query endpoints from the browser; carving those paths out for the Toolbelt would break the UIs. The read routes (`apps/victoria{logs,metrics}/httproute-aiops-read.yaml`) allow GET only on exact query paths (`/select/logsql/` prefix for VL; `/api/v1/query` and `/api/v1/query_range` EXACT for VM), no Authentik, and a Traefik `ipAllowList` of Frigg's `10.0.11.30/32` (`monitoring-namespace/middleware-aiops-read-ipallow.yaml`; Traefik sees real client IPs because its Service is `externalTrafficPolicy: Local`). `/insert/`, `/delete/`, `/api/v1/admin/*`, snapshots and every write path are not routable on these hosts.
- **Verify the read routes after the DNS apply (operator, once):** from Frigg `curl https://metrics-read.niflheim.xiiisins.com/api/v1/query?query=up` is 200; from Gna or the workstation the same is `403`; from Frigg `.../api/v1/admin/tsdb/delete_series` and `https://logs-read.../insert/jsonline` are 404. A `403` from Frigg means Traefik is not seeing Frigg's real IP (check the Traefik Service's `externalTrafficPolicy`).
- **VictoriaLogs time arguments:** the `logs.query` tool turns relative times (`15m`, `2h`, `1d`) into RFC3339 instants client-side (VL's `start`/`end` do not take durations); the default window is the last 15 minutes. Metrics are bounded to 50 series x 120 points (evenly thinned, latest point kept) so a wide range query cannot flood the model.
- **A `#diagnoses` thread gets a closing note when there is nothing left to resolve (2026-10-03).** Replay incidents are synthetic and never send a recovery, and a real alert can recover while the agent is still running, before any thread exists for the recovery to update. Both used to leave the thread at "firing" forever. After the thread is posted the ingest workflow re-reads the incident (`Get final state`); if it is a replay, or every alert is already `resolved`, it posts a closing note ("Replay run finished" / "RESOLVED: the alert recovered before this analysis was posted") and marks the incident `resolved`. The Toolbelt's `set_state` tolerates a `resolved` incident that is still `running`. A real alert that recovers AFTER the thread is posted still goes through the normal recovery path. Old test threads from before this change have no note; delete them.
- **A Terraform apply of `terraform/netbox` at default parallelism OOM-kills the NetBox pod, and then Semaphore's dynamic inventory gets `Bad Gateway` (2026-10-03).** The `aiops-*` playbooks' guard then correctly refuses an empty inventory (`target_host in groups['all']` fails): the symptom looks like a bad executor identity but is NetBox being down. Check `kubectl -n netbox get pods` (OOMKilled restarts) and retry when it is Ready; always apply NetBox with `-parallelism=2`.
- **The bot's UCG policy must allow `gateway.discord.gg`, not only `discord.com` (2026-10-03).** discord.py logs in over REST (`discord.com`) and then holds a WebSocket to the gateway: with only the REST domain allowed the bot starts, then dies with `'NoneType' object has no attribute 'sequence'` after a gateway TimeoutError, and the Ratatoskr role's `ready` check fails. Test egress with Python (the host has no curl): `python3 -c "import socket;socket.create_connection(('gateway.discord.gg',443),8)"`.
- **A Discord webhook cannot carry buttons or read reactions, and a mention delivers message content without the privileged intent (2026-10-03, 10e).** Interactive approval needs a bot; mention-only chat means the bot asks for NO privileged gateway intent (`Intents.default()`, `message_content` off). A button's `custom_id` carries the proposal id and the params hash, and the buttons are `discord.ui.DynamicItem`s (discord.py >= 2.4; Debian 13 ships 2.5) so cards posted before a restart keep working.
- **One SQLite connection is shared by the HTTP threads and the action-executor thread, and Python's `sqlite3` does not serialise it (2026-10-03).** Every read AND write in `core.py`/`actions.py` holds one re-entrant lock; a read without it showed up as an intermittent `KeyError` in a test as soon as the executor ran concurrently. `decide()` also snapshots the proposal BEFORE starting the executor thread, or a fast run would make the response say `succeeded` instead of `approved`.
- **`AIOPS_RESULT` appears inside ansible's `debug` output as an ESCAPED JSON string (`"msg": "AIOPS_RESULT {\"ok\": true}"`), and the two replay actions cannot print their own stats (2026-10-03).** `actions.parse_output` tries the raw, unescaped and double-unescaped forms; actions with `semaphore.result_from: recap` (`replay-role-check`, `replay-role`) take `ok`/`changed` from the target host's PLAY RECAP line instead.
- **Per-source path rules on Gná's Caddy use a CEL matcher: `@x expression path('/webhook/aiops/chat*') && !remote_ip('10.0.11.222')` (2026-10-03).** Validated with a real Caddy (2.11) and a request matrix before merge (a wrong source gets 404, the right one passes through, everything else 404); the listener's `allowed_cidrs` is the union, the per-path rules narrow it.
- **`IPAddressDeny=` in a unit inside an UNPRIVILEGED LXC is best effort (2026-10-03).** It needs cgroup BPF, which an unprivileged container may not have; the Ratatoskr unit carries an RFC1918 deny with the few endpoints it needs allowed, but the UCG policy is the boundary. Do not claim the unit enforces it without testing.
- **Ansible `-e key=false` passes the STRING `"false"`, which Jinja treats as true (2026-10-03).** Use `-e '{"key": false}'` (or a group_var) when testing a boolean template switch; this made an `aiops_toolbelt_actions_enabled` render look broken when it was fine.
- **A secret that must be present for a feature to be safe is a REQUIRED file in the Frigg loader, not an optional credential (2026-10-03).** `AIOPS_TOOLBELT_EXTRA_FILES` fails the start when the approver token or the operator id is missing or short, and the role asserts them in preflight: the API must never run with approvals on and no approver.
- **The model writes a unit as `zabbix-agent2`, not `zabbix-agent2.service`.** The registry pattern requires the suffix, so the proposal was refused (`proposal_rejected`, 1 problem) and the autonomous fix never ran (found live on the first masked-unit soak run, 2026-10-03). Why: the model paraphrases unit names. How to apply: the Toolbelt completes a bare unit name before validation (`Engine._tidy_params`; the pattern and the per-host allow-list still decide) and the prompt asks for the full name; the rejection journal line now carries `why` (the first problem). Symptom: a diagnosis that names the right runbook but no proposal appears in the thread, plus a `proposal_rejected` line in `journalctl -u aiops-toolbelt`.
