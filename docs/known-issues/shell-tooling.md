# Known gotchas — Shell / tooling

*Migrated from `CLAUDE.md`. Recovery commands + rules. Incident retros in [`../incidents/`](../incidents/).*

## Shell / tooling

- **BSD sed (macOS) does NOT support `\s` regex shorthand.** Patterns like `\s+` or `\s*` match literally `\s` followed by `+`/`*` (zero or more `s` characters in some interpretations), never whitespace. Result is silent no-op: the substitution doesn't fire, the original line passes through verbatim. **Critical risk class for redaction-before-print**: `sed -E 's/(=\s*)".*"/\1"<REDACTED>"/'` looks safe but does nothing on macOS, leaking the value to the transcript. Use `[[:space:]]` instead (portable across BSD + GNU). Surfaced TWICE on 2026-05-25 within 30 min — first against the Proxmox tfvars file (token literal printed → rotation triggered), second against AdGuard config (less harmful, but same class). **Rule:** any redaction regex MUST use `[[:space:]]` or hard-coded literal spaces; `\s` is forbidden in user-facing print pipelines.
- **GNU tar `--strip-components=N` strips slash-separated path components, not directory levels.** Tarballs with leading `./` prefix (common — e.g. `./AdGuardHome/AdGuardHome/file`) have `.` as the first component. `--strip-components=1` removes the `.`, leaving the wrapper directory + file path intact. To strip `./AdGuardHome/`-style wrappers needs `--strip-components=2` for `./`-prefixed tarballs OR `--strip-components=1` for plain `AdGuardHome/`-prefixed. **Robust pattern: extract to tempdir + `find` the binary + `cp -a` to the install dir.** Avoids strip-components math entirely + handles broken state (where the path you'd extract over is a stale file vs dir). Symptom of misuse: files land at `<dest>/<wrapper>/<file>` (`/opt/AdGuardHome/AdGuardHome/AdGuardHome` — binary becomes a directory containing the binary; service fails to start with "Is a directory"). Surfaced 2026-05-25 in the `adguard` role; now uses temp-extract + cp.
- **Ansible `ansible.builtin.unarchive` fails with `[Errno 20] Not a directory`** when `--strip-components=N` renames a tarball directory entry to a destination path that exists as a regular file. The module's post-extraction validation stat()s the original (pre-strip) tarball-listed paths against the destination; with strip-components, those paths don't match where files actually landed. Workaround: drop unarchive, use `command: tar` directly (and the temp-extract pattern above to sidestep the strip-components quirks). Surfaced 2026-05-25.
- **fish heredocs `<<EOF` don't work.** Use pipes or temp files. (See feedback memory `feedback_fish_heredocs.md`.)
- **fish command-substitution collapses newlines when echoed via variable.** `set -l var (cmd)` captures list-of-lines; `echo $var | grep` joins with spaces. Preserve structure: pipe directly (`cmd | grep`), or iterate the list (`for line in $var`).
- **`kubectl exec` warning lines pollute scripted parsing.** Multi-container pods print `Defaulted container "X" out of: ...` to stdout. Always pin with `-c <container>` for scripts.
- **`Bash` tool calls don't inherit the operator's interactive shell PATH.** `/opt/homebrew/bin` (Homebrew on Apple Silicon) is in the shell-rc-loaded PATH but absent in the non-interactive shell `Bash` invokes. `op`, `terraform`, `vault`, `kubectl`, `helm` may all not-found despite being installed. Fix: prefix the command with `PATH="/opt/homebrew/bin:$PATH"` or invoke via absolute path. The `homelab-env` shim cache (`. ~/.cache/homelab/env.sh`) sources fine once PATH points at `op`. Surfaced 2026-05-25 during NetBox token verification.
- **Pipe-induced subshell hides env exports.** `cmd-that-exports | tail` runs the exporting cmd in a subshell — exports never reach the parent. Symptom: `homelab-env --refresh 2>&1 | tail -5` looks like it worked, then `echo $NETBOX_API_TOKEN` is empty. Verify cache via the file directly (`grep -E '^export NAME=' ~/.cache/homelab/env.sh | wc -c`), not via inspecting parent env vars. Surfaced 2026-05-25.
- **Inline redaction must handle bash AND fish syntax — or skip redaction entirely.** `homelab-env` writes both `~/.cache/homelab/env.sh` (bash `export KEY=value`) and `~/.cache/homelab/env.fish` (fish `set -gx KEY 'value'`) — `=` vs space + quoting differ. A single regex matching `KEY=.*` redacts bash but lets the fish line through verbatim, leaking the secret. **Rule:** when verifying secret presence in cache, use length-only checks (`wc -c`, `${#var}`) — never try to inline-redact the value in stream output. If you must show a token's identity, hash it (`shasum`, first 8 chars) or count its length. Surfaced 2026-05-25 — NetBox admin API token leaked verbatim via fish-line miss, rotated by operator.
- **`op item edit <id> --title` cannot rename SSH-Key items or malformed Password items.** SSH-Key items error `SSH Key item editing in the CLI is not yet supported`; a Password item missing a `ps` value errors `validateVaultItem ... Password item requires ps value` (the validator rejects ANY edit — including title-only — when the item fails validation). Both must be renamed in the 1Password **app GUI**; Login / SecureNote / API-credential items rename fine via CLI. Diagnostic: run the failing edit without `2>/dev/null` to see which class it is. Surfaced 2026-05-30 during the 1P naming reorg (convention in [`docs/architecture/identity-secrets.md`](../architecture/identity-secrets.md)).
- **zsh: `local path` inside a function silently empties `$PATH` for the rest of that function's scope (incl. nested function calls) — `path`/`PATH` are a special tied array/scalar pair.** `homelab.sh`'s `homelab-env` and `vault-homelab-env` both declared `local refresh=0 clear=0 path removed=0` (intending `path` as a plain cache-clear loop var). Under zsh (this repo's default shell), that declaration breaks the `path`↔`PATH` binding for the function's scope, so every external command called after it — including nested calls like `stat`/`vault` inside `__vault_homelab_cache_age_seconds` — fails `command not found`, even though those binaries resolve fine at top level (`which`/`command -v` outside the function succeed). Under bash, `path` has no special meaning and the bug is invisible — this only bites zsh, hence the "bash/zsh" header comment never caught it. **Reproduce:** `zsh -c 'f() { local path; command -v vault; }; f'` → empty PATH, `command -v` fails. **Fix:** never `local`-declare a variable literally named `path`, `PATH`, `fpath`, `cdpath`, or `manpath` in a zsh function; homelab.sh's loop var was renamed to `cache_file`. Surfaced + fixed 2026-09-03 during Immich shape work — this had silently broken BOTH shim functions for any cold-cache zsh invocation until then.
- **`vault token lookup -format=json` prints the literal token value in `.data.id`** — piping/reading that output puts the secret straight into a transcript or log. **`vault token lookup` has NO `-field` flag** (only `-format`; `-field` is a `read`/`write`/`kv get`-family flag, and `token lookup` uses a different internal command type that doesn't support it — `flag provided but not defined: -field` if you try it, caught 2026-09-03 writing `rotate-vault-root-token`). The safe pattern: capture the full `-format=json` output into a local/shell variable, pull only the field you need via `jq -r '.data.<field>'`, then discard the variable (`unset`/`set -e`) — never let the captured JSON itself reach stdout, a return value, or a log line. Surfaced 2026-09-03 — a root-token lookup leaked into a Claude session transcript by displaying `-format=json` directly; recovery was flag-immediately + recommend rotation (see vault.md).
- **`homelab.sh`'s `stat -f %m <file>` (BSD/macOS mtime syntax) breaks on Linux — GNU `stat` treats `-f` as "show filesystem, not file, status" and errors `cannot read file system information for '%m'`.** Found on Frigg (Debian, GNU coreutils) running `vault-homelab-env`'s cache-freshness check (`__vault_homelab_cache_age_seconds`) — degraded gracefully (treated cache as stale, always re-fetched) rather than hard-failing, which is why it went unnoticed. **Fixed 2026-09-03**: `date -r "$file" +%s` gives mtime as epoch seconds identically on BSD *and* GNU `date` — replaced `stat -f %m` in both `__homelab_cache_age_seconds` and `__vault_homelab_cache_age_seconds`.
- **FIXED 2026-09-04 (was open 2026-09-03–04, bit twice): `zsh` prints `value=<current-value>` to stdout, unprompted, as a side effect of redeclaring `local value` on a variable that's already local in the current scope and already holds a value from a prior loop iteration — `bash` does not.** Root cause of two separate transcript leaks (2026-09-03 and 2026-09-04). `__homelab_cache_write`'s `for env_var in "${vars[@]}"; do local value; ...; done` redeclared `local value` on every iteration; from the second cached var onward, each redeclaration dumped the *previous* iteration's value (Vault token, AWS keys, AppRole secrets, every API token, AdGuard password — every cached credential) to stdout, with no explicit `echo`/print anywhere in the file and no `xtrace` involved. **Minimal repro, decisive:** `f() { local x; x=1; local x; }; f` prints `x=1` unprompted under `zsh`, prints nothing under `bash` — same script, same function body, shell-family-dependent only. This is why the operator's own interactive **fish** shell never saw it (fish's `set -l` scoping has no equivalent behavior) while Claude's non-interactive `zsh`-based Bash tool hit it reliably, and why an earlier investigation pass (2026-09-03) that ruled out `xtrace`/`SHELLOPTS`/explicit-echo still came up empty — it never isolated shell *family* as the variable, since both the operator and Claude were assumed to be running some POSIX-ish shell without distinguishing zsh from bash from fish. **Fix:** declare `value` once at function scope (`local entry env_var value ts ...` at the top, matching the pattern `__vault_homelab_cache_write` already used correctly), not redeclared inside the loop body. **Standing rule, now belt-and-suspenders rather than the only defense:** still never `cat`/display the raw output of `homelab-env`, `vault-homelab-env`, or `set-vault-token` in a Claude tool call — verify via hash-only/length-only/exit-code checks. Full incident: [`../incidents/2026-09-03-claude-transcript-secret-leak.md`](../incidents/2026-09-03-claude-transcript-secret-leak.md).
- **Reference machine-accessed 1P items by UUID, not title.** The `homelab-env` shim (`.config/fish/conf.d/homelab.fish` + `.config/scripts/homelab.sh`) and TF read credentials via `op://Homelab 2.0/<item-UUID>/<field>` (named `__op_*` vars), so 1P items can be renamed/reorganised without breaking automation. `op://` accepts a UUID in the item slot exactly like a title. Find UUIDs: `op item list --vault 'Homelab 2.0' --format=json | jq -r '.[]|"\(.id)\t\(.title)"'`. Surfaced 2026-05-30 Wave S1.
