# 1.0 stabilization plan

*Drafted 2026-05-27, right after Phase 5h.3 closed and the homelab hit the "core infra is up + monitoring + drift detection" milestone the design has been building toward. Captures the pre-build-on-top hardening pass before adding more services (Jellyfin, Immich, n8n, Privatebin, Startpage) on the foundation.*

## Framing

The homelab is at 1.0 — the foundation works. Phase 5h.3's drift-check baseline closed the last gap that made it merely *converged* rather than *self-aware*: any disagreement between Git and reality now surfaces as a Discord alert within 6 hours. Combined with VictoriaMetrics + VictoriaLogs + Zabbix catching runtime drift, the homelab tells the operator when something's wrong rather than waiting to be looked at.

What remains is character rather than core:
- **Phase 6 (Vault OIDC)** — operator-UX polish; humans still look up secrets in 1P
- **Phase 7 (jotunheim K3s)** — second failure domain + "can implode" learning sandbox
- **App backlog** (Jellyfin, Immich, n8n, …) — using the homelab, not building it
- **Phase 8b / 9** — refactors deferred by choice (Helm → vm-operator, ESO → Vault Agent)

Before any of those land, this plan hardens what's already deployed. The goal is **measurable confidence**, not neatness — each wave should leave the foundation more trustworthy, not just tidier. Cosmetic items are deliberately deferred unless they fall out of other work.

## Honest gap in the "1.0" framing

Failure-domain depth is the next axis of improvement and Phase 7 is the structural answer. Single cluster, single PG-leader-at-a-time, single NAS. This stabilization plan doesn't close those — they're explicit Phase 7 work. It hardens what we *do* have so that when we add services to it, we don't compound fragility.

**Status: ✅ complete (2026-05-31).** All six items closed:

### Findings (2026-05-31 read-only headroom pass)

- **Cloudflared headroom — fine.** 3/3 replicas, 12 edge connections (4/replica to AMS PoPs), CPU **2m vs 100m request**, memory **~50Mi vs 128Mi**, logs clean (only the benign QUIC receive-buffer + a one-off feature-fetch DNS warning). A handful of restarts over ~5 days from 12h-interval liveness flaps, all clean recoveries. Proposed "saturated" definition: any pod >300m CPU or >256Mi mem, lost edge-connection registration, or >10 reregistrations/hr. Headroom ~5× before hitting requests. No follow-up.
- **CoreDNS rewrite scaling — fine.** 4 `rewrite name exact` lines today (`authentik.midgard`, `wiki.midgard`, `wiki` apex, `netbox.niflheim`), git == live. Grows ~1 per K8s-fronted internal service; exact-match rewrites are performance-irrelevant until hundreds/thousands. A wildcard rewrite is **not** viable — it would catch LXC/VM FQDNs the exclusion rule forbids. No follow-up.
- **Authentik resource growth — fine.** ~34 managed Authentik objects across 6 services (8 policy-bindings, 7 providers, 7 applications, 8 groups, 1 user; property/scope mappings are data-sourced, not TF-defined). ~3–4 resources/service, `terraform plan` completes in seconds. No concern until ~hundreds. No follow-up.
- **AppRole rotation — re-minted + root-caused + closed (2026-05-31).** The "enforced 2026-06-28 expiry shorter than the 90d role TTL" was traced to the `approle` auth **mount's `max_lease_ttl`** sitting at Vault's 768h (32d) default, which clamps every role's `secret_id_ttl`. Fixed by `tune { max_lease_ttl = "2160h" }` on `vault_auth_backend.approle` in `terraform/vault/` (in-place); the operator applied it + re-minted, and the new `ansible-local` SecretID now carries a full **90-day** expiry (2026-08-29). Surfaced two adjacent fixes: the `rotate-approle` paste-footgun (new accessor pasted into the `username`/role_id field broke `set-vault-token approle` — corrected in 1P) and `vault-root-token` reading a stale 1P title (now UUID). All in CLAUDE.md gotchas; the handler-skip follow-up is in `open-questions.md`.
- **Vault iSCSI fsGroup chown-init — re-scoped + closed.** Moot for Vault: it moved iSCSI → local-path 2026-05-30, so the fsGroup-on-iSCSI quirk no longer applies. The only remaining iSCSI chown-init in the cluster is **garage-meta** (10Gi LMDB LUN on Volume2), verified healthy. Nothing left to validate.
- **Authentik↔Patroni-VIP connection-churn — ROOT-CAUSED + FIXED (2026-05-31).** Not `on-marked-down shutdown-sessions` (ruled out: zero backend DOWN/UP events). Cause: the `haproxy` role's `defaults` block sets `timeout client/server 50s`, which the `mode tcp` `pg_write` listener inherited — so HAProxy reaped any PG connection idle >50s. Confirmed via HAProxy log termination flags: ~5.5k/day `cD` (client-timeout-during-data) terminations with `Tt≈50000ms`. Authentik's `django_channels_postgres` LISTEN connection is the most visible victim (logs the SSL-EOF on next reuse); benign (auto-reconnect, readiness green) but wasteful + noisy, and broader than Authentik (any pooled idle conn). **Fix:** `timeout client/server 30m` + `option tcpka` scoped to the `pg_write` listener only (stats keeps 50s), matching the upstream Patroni HAProxy reference. Reloaded across the trio (Hlin/Eir/Snotra); verified no post-reload connection reaped at 50s on the VIP holder. CLAUDE.md HAProxy gotcha added.

These are real, but they don't block "build on top of":

## Recommended sequence

1. **S1 (validation)** first — cheap, and might surface things that change downstream priorities
2. **S7 (fragility audit)** second — most likely to expose real issues before they bite during build-on-top
3. **S2 (recovery)** + **S3 (role debt)** in parallel — they don't conflict
4. **S4 (observability) / S5 (pins) / S6 (cleanup)** anytime

Estimated total: 2-3 sessions of focused work, not weeks.

## Definition of "done" for the 1.0 stabilization

When closed, this plan flips the homelab's posture from "everything works" to "everything works AND we can prove it works AND we'll know when it stops working." Concrete signals:

- Last `terraform plan` across every module: zero drift
- Last drift-check cycle: zero `changed=`
- Every recovery-critical artifact: documented out-of-band copy + verified-current
- Every alert path designed in: validated by a synthetic failure
- Every IaC version: concrete or has a decision row
- Every accumulated role-debt item: closed or has a follow-up phase

At that point, building on top of the homelab — Jellyfin, Immich, n8n, Phase 6, Phase 7 — is adding to a foundation we trust, not extending one we hope works.
