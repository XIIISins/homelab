    Frigg (queen of Asgard, sees all fates — matriarch of the handmaiden-named PG/HAProxy trios Fulla/Vör/Idunn + Hlin/Eir/Snotra, and a third member of the Hugin/Munin naming family) is an always-on, HA, homelab-resident VM. **Primary role:** a persistent home for `claude remote-control` sessions so Claude Code remote-control no longer hinges on the MacBook staying awake — the MacBook's 1Password locks on screen-sleep, which kills any Claude session leaning on MacBook-held creds; Frigg never touches 1P. **Secondary role:** operator SSH for by-hand ops.     Design decisions settled in the 2026-05-31 design conversation (owner-chosen):
    - **Form factor: VM** (own kernel; native `/dev/net/tun`, so Tailscale skips the LXC `device_passthrough` + `root@pam` dance). Stronger isolation boundary than an LXC for the most-privileged box.
    - **One box, both roles** (watchtower primary, jump-host secondary). The bastion framing was the wrong emphasis — this is a Claude-execution host first.
    - **Vault-AppRole-only secret access** — no `op`/1P on the box. This is *why* the always-on + AppRole combination is the right shape: the box self-authenticates to Vault forever from a seeded SecretID, with no interactive unlock in the loop.
    - **HA via Proxmox `ha-manager`** — requires shared storage, but every other VM/LXC disk is local-LVM-thin (not shared, and LVM-thin can't `pvesr`-replicate — that's a ZFS feature, and we're not on ZFS). So Frigg's disk is the **deliberate exception on a Munin NFS datastore**. The "VM disks = local LVM-thin" invariant is PG-latency-specific (NFS fsync + WAL over 1GbE) and doesn't apply to a control node. HA **cold-restarts** Frigg on a survivor (~1-2 min; stateless-by-design → reconverges) as long as ≥2/3 Proxmox nodes hold quorum (lose 2 → inquorate → HA fences/halts → MacBook break-glass). A QDevice for tighter quorum is a separate future item, not this phase.
    - **Claude integration: `claude remote-control` server mode** as a systemd unit (`--spawn worktree`, which dovetails with the repo's worktree-isolation convention). Connection is **outbound-HTTPS-only** → no inbound exposure, no port-forward/MetalLB/Tailscale needed for the Claude flow (Tailscale still earns its place for the by-hand SSH path). Driven from the **Claude mobile app / claude.ai/code**; all execution stays on-box. Auth via a `claude setup-token` 1-year OAuth token (subscription-based — minted once interactively on the MacBook, stashed in Vault, box pulls it) or the `apiKeyHelper` Vault hook. Remote-control requires a claude.ai subscription (not API-key) — already held.
